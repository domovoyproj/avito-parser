1. P0: конфигурация → безопасность и воспроизводимые offline проверки.

3. P2: UI и экспорты → backup/restore → эксплуатация и измерение нагрузки.

## Принципы реализации
Каждая крупная Issue — epic: до работы разбить на PR размером в одну проверяемую задачу. Сначала фиксируем baseline и regression, затем меняем код. SQLite оставить до доказанного bottleneck; PostgreSQL/Redis/очередь добавлять только по измерениям. Не обещать exactly-once для внешних уведомлений. Не менять весь стек или фронтенд без отдельного обоснования. Все API и старые БД мигрировать совместимо. Не обходить CAPTCHA и не повышать нагрузку на источник; при блокировке останавливаться с диагностикой.

## Продолжение любой моделью
Прочитать AGENTS.md и выбранную Issue. Обновить graphify, проверить affected и исходники. Оставить в Issue точные изменения, PR/commit, результаты тестов, ограничения и следующую задачу. Не закрывать эпик по одному частичному PR. Общая готовность: чистая установка, green offline CI, проверенное восстановление backup и документированные runbooks.

# Эксплуатация

Перед обновлением сделайте SQLite backup через `Database.backup(path)`. Это онлайн-копия с проверкой integrity_check, а не копирование открытого файла вместе с незавершённым WAL. Для восстановления остановите web/bot/CLI, сохраните текущую БД отдельно и установите проверенный snapshot на путь `config.db_path`; затем запустите один процесс для миграции. Не открывайте более новую схему старой версией приложения.

Первый администратор создаётся локально командой `python setup_admin.py`. Стандартного пароля нет. Смена пароля отзывает сессии. Для HTTPS включите `WEB_SECURE_COOKIES=true`; reverse proxy должен передавать корректные host/scheme. `/health` проверяет процесс, `/ready` — доступность мигрированной БД, без обращений к Avito или Telegram.

Docker работает от UID/GID 10001. Перед `docker compose up --build` создайте папки `data`, `exports`, `logs`, `config`; перенесите `.env` в `config/.env` и предоставьте UID 10001 запись в эти папки. Монтируется вся папка конфигурации: атомарная замена файла не работает с отдельным bind mount `.env`. Локальный запуск продолжает использовать корневой `.env`; путь можно изменить через APP_ENV_FILE. Значения из окружения процесса имеют приоритет над файлом.

Общие lease SQLite предотвращают одновременную проверку одного поиска процессами web и bot. Уведомления фиксируются вместе с объявлением и доставляются из outbox по получателю. Доставка at-least-once: авария после успешной отправки до фиксации результата может вызвать повтор. Проверяйте статусы failed и возраст pending в notification_outbox. Retry ограничен восемью попытками, 429 откладывает отправку; quiet hours не расходуют попытки.

Команды проверки: `python run_offline_tests.py`, `python -m ruff check . --select E9,F63,F7,F82`, `python -m pip_audit -r constraints.txt`, `npm ci && npm run build`. UI QA: запустите `python tools/ui_fixture.py` в отдельном терминале и `python tools/ui_smoke.py --out <folder>`; используются временная БД и локальные fixture-данные.

LLM cache и бюджет текущей реализации действуют внутри процесса: TTL 24 часа, максимум 1024 записей и 100 запросов за календарный день. Межпроцессный постоянный бюджет, метрики и автоматизированная проверка восстановления остаются задачами roadmap. API экспортирует до 10 000 строк и явно возвращает 413 для большей выборки; асинхронные крупные экспорты ещё не реализованы.

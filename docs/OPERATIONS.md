# Эксплуатация

Перед обновлением: `python manage_db.py backup backups/snapshot.db`. Это SQLite online backup с integrity_check, допустимый одновременно с записью. Для восстановления остановите web/bot/CLI и выполните `python manage_db.py restore backups/snapshot.db --offline`. CLI проверяет integrity/FK/version до замены, отказывается при существующих WAL/SHM, сохраняет текущую базу в sibling backups и атомарно устанавливает snapshot; затем запустите один процесс для миграции. Если после остановки остался WAL, выполните checkpoint штатными средствами SQLite и проверьте его успех; не удаляйте незавершённый WAL вручную. Более новую схему старой версией приложения не открывать.

Первый администратор создаётся локально командой `python setup_admin.py`. Стандартного пароля нет. Смена пароля отзывает сессии. Для HTTPS включите `WEB_SECURE_COOKIES=true`; reverse proxy должен передавать корректные host/scheme. `/health` проверяет процесс, `/ready` — доступность мигрированной БД, без обращений к Avito или Telegram.

При обновлении существующий admin/admin123 отключается вместе с сессиями. Для восстановления локально: `python setup_admin.py --reset-password`; пароль вводится скрыто, минимум 12 символов. Пользователи с собственными паролями сохраняются. Команда восстановления требует локального доступа к файлам установки.

Docker работает от UID/GID 10001. Перед `docker compose up --build` создайте папки `data`, `exports`, `logs`, `config`; перенесите `.env` в `config/.env` и предоставьте UID 10001 запись в эти папки. Монтируется вся папка конфигурации: атомарная замена файла не работает с отдельным bind mount `.env`. Локальный запуск продолжает использовать корневой `.env`; путь можно изменить через APP_ENV_FILE. Значения из окружения процесса имеют приоритет над файлом.

Общие lease SQLite предотвращают одновременную проверку одного поиска процессами web и bot. Уведомления фиксируются вместе с объявлением и доставляются из outbox по получателю. Доставка at-least-once: авария после успешной отправки до фиксации результата может вызвать повтор. Проверяйте статусы failed и возраст pending в notification_outbox. Retry ограничен восемью попытками, 429 откладывает отправку; quiet hours не расходуют попытки.

История отдельных проверок хранится в `monitoring_runs` и доступна на странице `/monitoring` и через `GET /api/monitoring/runs`. Записи старше 30 дней удаляются при следующей записи; `run_id` исключает повторную вставку того же результата. Хранятся только тип ошибки и счётчики, без HTML страниц, cookies и токенов. Если мониторинг долго не запускается, старые записи остаются до следующей проверки.

Личные списки доступны через `/watchlists`. При первом обновлении до схемы SQLite 8 старое глобальное избранное копируется в основной список каждого существующего пользователя; последующие запуски эту копию не повторяют. Старая колонка `items.is_favorite` остаётся для старых CLI-вызовов, а web API фильтрует избранное по текущему пользователю. Адресные Telegram-оповещения требуют личной привязки: в панели получите одноразовый код и отправьте `/link КОД` боту из личного чата. Код хранится только как хеш и действует 10 минут. Оповещение о достижении целевой цены помещается в общий outbox при снижении цены; повтор той же цены и чата подавляется ключом события. Глобальные уведомления администратора остаются отдельными.

Команды проверки: `python run_offline_tests.py`, `python -m ruff check . --select E9,F63,F7,F82`, `python -m pip_audit -r constraints.txt`, `npm ci && npm run build`. UI QA: запустите `python tools/ui_fixture.py` в отдельном терминале и `python tools/ui_smoke.py --out <folder>`; используются временная БД и локальные fixture-данные.

LLM cache/бюджет разделяются через SQLite: TTL 24 часа, максимум 1024 записей и 100 запросов за календарный день. Резервирование атомарное, неудачные вызовы расходуют бюджет. Метрики администратора: /api/metrics (queue age/status, jobs, cycle duration/errors, DB size). JSON logs содержат run/search IDs и redaction. Active/quiet hours и календарный бюджет используют timezone процесса; согласуйте timezone всех web/bot/CLI процессов.

CSV/XLSX из каталога создаются фоновыми persistent jobs: очередь максимум 20 активных задач, выборка максимум 1 000 000 строк, batches по 1000, XLSX write-only. /exports показывает прогресс и файлы. Worker возобновляет прерванные задачи после lease takeover; повторяет snapshot целиком, поэтому данные могут отражать более позднее состояние. Старый GET export API ограничен 10 000 строками с явным 413. Viewer использует этот read-only путь. Завершённые файлы не удаляются автоматически: удаляйте ненужные экспорты согласно своей политике хранения; ссылка на отсутствующий файл возвращает 410.

Релиз: `python build_release.py`, затем проверка `python -m unittest test_release -v`. Windows ZIP/Linux TAR включают routers/repositories и constraints; локальные DB/.env/logs не включаются. CI проверяет импорт из распакованного ZIP и состав обоих архивов, Docker UID/readiness/restart. Обновление на реальной машине начинать после зелёного CI и backup, затем /ready → login → offline просмотр каталога → export. Live внешние интеграции проверять с собственными учётными данными. Baseline и критерии профилирования: BENCHMARKS.md.

# Проверка качества скоринга

Метки в карточке объявления сохраняются в `item_feedback_events` вместе со снимком score, grade и версии правил. Повторная отправка той же метки и заметки не создаёт новое событие. Отчёт `/feedback` использует последнюю метку каждого пользователя для объявления; охват считает уникальные объявления с метками относительно всех объявлений с выбранными фильтрами. История пользователя видна ему самому; агрегаты доступны авторизованным пользователям. Порог 30 меток и 10 разных объявлений лишь открывает возможность анализировать калибровку, но не меняет правила автоматически.

Перед изменением правил сделайте backup БД и выполните `python tools/evaluate_feedback.py data/avito_parser.db --out offline-feedback.json`. Файл содержит только метки, баллы, классы, версии и полноту сигналов без идентификаторов, названий, заметок и URL. Сравнивайте долю ложных срабатываний по версиям; баллы не трактуются как вероятность продажи. Экспортные файлы храните вне репозитория.

# Проверка и обновление 2.7.0

Дата: 2026-11-13. Исходная версия: main `558723b22676a35dd51158290e13f84df39247bc`.
Рабочая ветка: `feat/deal-radar-reliability`.

## Что проверено

Проверены связи модулей через Graphify и исходники основного пути: HTTP/браузер → извлечение → сохранение и скоринг → мониторинг → outbox → Telegram/webhook. Дополнительно проверены миграции, авторизация/роли/CSRF, списки, фильтры, экспорт, упаковка и пользовательские сценарии панели. Это не независимый пентест и не подтверждение качества реального рынка.

### Найдено и исправлено

- Ограничение доступа действовало на отдельный поиск и терялось после перезапуска. Общая таблица `source_access_state` теперь хранит интервал запросов и паузу источника. HTTP, браузер, разовый сбор, мониторинг и отдельные процессы используют одну SQLite-очередь. При 403/429 или CAPTCHA автоматические запросы прекращаются; учитывается `Retry-After`, включая HTTP-date. Паузы 5/15/60 минут, не менее ответа сервера, максимум 24 часа. Уже выполняющиеся запросы не могут быть отозваны задним числом.
- Только явное действие ручного восстановления с видимым браузером может открыть источник во время паузы. Наличие открытого окна само по себе не снимает ограничение; нужен успешно распознанный результат. Автоматического решателя CAPTCHA нет.
- Повторяющиеся страницы могли расходовать всю глубину. Оба движка останавливаются, когда на странице нет новых ID. Параметр страницы заменяется корректно, без дублирования `p` или потери фрагмента URL.
- Ошибка сохранения/обработчика страницы могла повторять сетевой запрос. Обработчики вынесены за пределы повторов загрузки. Браузер закрывается в `finally`, в том числе при отмене.
- Короткая карточка поиска стирала детальные поля и ухудшала скоринг. Фото, характеристики, описание и известные поля продавца сохраняются до повторного расчёта. Цена не подменяется старой, если новая неизвестна.
- Строка цены склеивала все цифры, включая рассрочку/количество/копейки. Теперь извлекается первая денежная сумма, в целых рублях, с обычными и узкими неразрывными пробелами.
- `is_hot_deal` мог оставаться true после ухудшения оценки. Теперь флаг всегда соответствует актуальной категории оценки.
- Проверка поиска ждала отправку очереди. Доставкой занимается существующий отдельный worker; медленные внешние каналы не задерживают мониторинг.
- Уведомления могли приходить с устаревшей ценой либо для скрытого/закрытого/зарезервированного или удалённого лота. Перед отправкой проверяется актуальная запись. Фильтры webhook (минимальная оценка и тип события) тоже применяются непосредственно перед отправкой.
- Фильтр «ниже рынка» пропускал неизвестную цену. Теперь для такого фильтра требуются цена и медиана соответствующего поиска. Форматтер использует переданную БД, медиану и честную подпись «Медиана вашего поиска».
- Тихие часы существовали в модели, но не в постоянном хранилище. Добавлены колонки и сохранение настроек; обновления из бота их не сбрасывают.
- Исправлена гонка избранного: быстрый переход к фильтру во время сохранения больше не оставляет пустой результат; повторный клик во время запроса исключён.
- При наличии версии схемы 11, но отсутствии FTS-таблицы, восстановление индекса не запускалось. Инициализация теперь также проверяет существование таблицы и пересоздаёт индекс при её отсутствии.
- Аудит исходного constraints нашёл 28 advisory entries в пяти пакетах. Обновлены aiohttp, certifi, filelock, opentelemetry-api и SoupSieve; повторный `pip-audit -r constraints.txt` не нашёл известных уязвимостей. Установщики теперь применяют constraints.
- Установщики всё ещё печатали устаревшие общие учётные данные после установки, хотя такой вход отключён приложением. Подсказки заменены созданием администратора через `setup_admin.py` с личным паролем; готовых паролей в выводе больше нет.

## Интерфейс

Новая общая палитра (светлая/тёмная), графитовая навигация, индиго-акцент, переработанный обзор с быстрыми действиями и объяснением этапов. Все 14 экранов используют общий слой `radar.css`; старые API и маршруты сохранены.

Карточки выгодных лотов показывают причину или риск, полноту данных и ссылку на объявление. Состояние источника выводится из API, без фиктивных live-метрик.

Администратору доступен экран `/notifications`: статистика очереди, история, фильтры, причина пропуска/ошибки и атомарный повтор только неуспешных событий. Токены, адрес webhook и сырые payload в истории не возвращаются. Доступ защищён существующими сессиями/CSRF и явной проверкой администратора.

Правила уведомлений задаются отдельно для уже настроенных получателей Telegram: оценка, новые лоты/снижения цены, доставка, медиана поиска, тихие часы. Пресет «Только выгодные · 70+» заполняет форму, но не применяет правила без сохранения. Произвольный получатель через этот API не добавляется. Тихие часы используют время сервера; одинаковое начало и окончание означают паузу на сутки.

## Установка и ограничения

Требуется **Python 3.11.5+**: исправленный filelock требует Python 3.11+, SoupSieve — 3.11.5+. CI matrix обновлена на 3.11/3.12/3.13, Windows/Linux; результаты удалённого CI нужно проверить отдельно. Локально подтверждён только Python 3.13.16. Проверка синтаксиса shell не означает проверку установки Linux.

Схема SQLite — **11**, миграция с сохранением существующих записей. Перед обновлением существующей установки выполните backup по OPERATIONS.md. Применение к пользовательской рабочей базе в этой задаче не выполнялось.

Live Авито, CAPTCHA на реальном маршруте, Telegram, webhook и LLM не проверялись и не включались. Токен и реальные ID получателей в новую копию не переносились. Подключённый токен не доказывает доставку: сначала выполните явную тестовую отправку из настроек. Уведомления о новых объявлениях не восстанавливаются автоматически за период, когда канал вообще не был настроен.

Доставка по-прежнему at-least-once: сбой после внешней отправки и до фиксации в БД может дать дубль. Нет гарантии доступа к Авито или отсутствия блокировок. Общий ограничитель контролирует запросы страниц, но не каждый внутренний ресурс Chromium. Существующие задачи разового сбора всё ещё в памяти процесса; после перезапуска они не продолжаются. Распознавание сайта и точность оценок на живых объявлениях требуют отдельной проверки; для медианы задавайте узкие поиски сравнимых товаров.

Следующий шаг: проверить удалённый CI и обновление на копии рабочей БД, затем выполнить один согласованный live-поиск и тест уведомления на реальном получателе. Эпики #10/#13 не закрывать до внешней проверки.
